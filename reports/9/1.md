# Открываем iptables

Работа выполнялась в виртуалке Arch Linux (`archlinux`, юзер `xen`, локальный доступ к консоли ВМ + проверка по SSH через настроенный ранее `lab-vm`).

## 1–2. Проверка `iptables` и исходных правил

Использованные команды:

```bash
iptables -V || true
systemctl list-unit-files | grep -E '^(iptables|nftables|firewalld|ufw)' || true
sudo iptables -L -n -v --line-numbers
```

Полученный результат:

```text

num   pkts bytes target     prot opt in     out     source               destination

```

Пакет `iptables` (`v1.8.13 (nf_tables)`) уже установлен в системе. Изначально все цепочки пустые, политики по умолчанию - `ACCEPT`.

## 3–5. Настройка правил `iptables` и проверка SSH

Чтобы не отрезать себе доступ, сначала добавляются все разрешающие правила (`lo`, `ESTABLISHED,RELATED`, TCP `22`, `ICMP echo-request`), и только в конце политика цепочки `INPUT` переводится в `DROP`.

Использованные команды:

```bash
sudo iptables -A INPUT -i lo -j ACCEPT
sudo iptables -A INPUT -m conntrack --ctstate ESTABLISHED,RELATED -j ACCEPT
sudo iptables -A INPUT -p tcp --dport 22 -j ACCEPT
sudo iptables -A INPUT -p icmp --icmp-type echo-request -j ACCEPT
sudo iptables -P INPUT DROP
sudo iptables -L -n -v --line-numbers
ssh -o BatchMode=yes lab-vm 'echo "SSH OK after iptables: $(whoami)"'
```

Полученный результат:


Все требуемые правила применены, лишние входящие соединения отбрасываются политикой `INPUT DROP`, а подключение по SSH работает (`SSH OK after iptables: xen`).

## 6. Транспортный протокол SSH

SSH использует транспортный протокол **TCP** (по умолчанию порт `22/tcp`), поскольку для интерактивной сессии и шифрованного канала важна надежная гарантированная доставка пакетов в правильном порядке.

## 7. Временное разрешение дополнительного TCP-порта и его удаление

Временно открыт порт `8080/tcp`, проверен в таблице `INPUT`, а затем удален ключом `-D`.

Использованные команды:

```bash
sudo iptables -A INPUT -p tcp --dport 8080 -j ACCEPT
sudo iptables -L INPUT -n --line-numbers
sudo iptables -D INPUT -p tcp --dport 8080 -j ACCEPT
sudo iptables -L INPUT -n --line-numbers
```

Полученный результат:

# Сохраняем

## 8–9. Сохраняются ли правила автоматически и как их сохранить

Нет, правила `iptables` живут только в оперативной памяти ядра и **после перезагрузки сбрасываются**.

В Arch Linux штатный способ сохранения - выгрузить текущие правила через `iptables-save` в файл `/etc/iptables/iptables.rules` и включить в автозагрузку службу `iptables.service` (при старте она автоматически запускает `iptables-restore /etc/iptables/iptables.rules`).

Использованные команды:

```bash
sudo iptables-save -f /etc/iptables/iptables.rules && sudo systemctl enable iptables.service
cat /etc/iptables/iptables.rules
```

Полученный результат:

```text
Created symlink '/etc/systemd/system/multi-user.target.wants/iptables.service' → '/usr/lib/systemd/system/iptables.service'.
# Generated by iptables-save v1.8.13 (nf_tables) on Sun Nov 22 23:44:41 2026
*filter
:INPUT DROP [0:0]
:FORWARD ACCEPT [0:0]
:OUTPUT ACCEPT [0:0]
-A INPUT -i lo -j ACCEPT

-A INPUT -p icmp -m icmp --icmp-type 8 -j ACCEPT

```
