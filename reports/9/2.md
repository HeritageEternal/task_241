# Открываем firewalld

Перед включением `firewalld` служба `iptables.service` из предыдущего задания отключена, а ее правила сброшены (`sudo systemctl disable --now iptables.service && sudo iptables -P INPUT ACCEPT && sudo iptables -F`), чтобы два фаервола не мешали друг другу.

## 1, 2, 5 (до изменений) и 12. Установка `firewalld`, активная зона, исходные правила и backend

Использованные команды:

```bash
sudo pacman -S --needed --noconfirm firewalld && sudo systemctl enable --now firewalld.service
sudo firewall-cmd --get-active-zones && sudo firewall-cmd --list-all && grep -i '^FirewallBackend' /etc/firewalld/firewalld.conf
```

## 3, 4, 6, 7 и 8. Проверка SSH, добавление сервисов по имени и доступ к Samba

**Можно ли добавлять доступ по названию сервиса?** Да - `firewalld` хранит готовые XML-описания популярных сервисов с нужными портами и протоколами (в `/usr/lib/firewalld/services/`), поэтому вместо ручного перечисления всех портов Samba (`137/udp`, `138/udp`, `139/tcp`, `445/tcp`) достаточно открыть сервис по имени `--add-service=samba`.

Проверено подключение по SSH, показано добавление сервисов `ssh` (уже был включен по умолчанию в зоне `public`) и `samba`, а также проверен доступ к Samba-ресурсу `//192.168.100.249/study`.

Использованные команды:

```bash
sudo systemctl start sshd.service && ssh -o BatchMode=yes lab-vm 'echo "SSH OK via firewalld: $(whoami)"'
sudo firewall-cmd --zone=public --add-service=ssh; sudo firewall-cmd --zone=public --add-service=samba
sudo firewall-cmd --zone=public --list-services && smbclient //192.168.100.249/study -U 'teacher1%LabPass123' -c 'ls'
```

Полученный результат:

```text

  teacher_ok.txt                      A       12  Sun Nov 22 23:29:29 2026
```

SSH работает, сервис `samba` добавлен в зону `public`, и подключение к шаре `//192.168.100.249/study` проходит успешно.

## 9, 10 и 11. Тестовый TCP-порт по номеру, сохранение постоянной конфигурации и проверка после `reload`

В runtime-конфигурацию добавлен тестовый порт `8080/tcp` и показан в `--list-all`, затем порт удален, рабочие правила сохранены в постоянную конфигурацию командой `sudo firewall-cmd --runtime-to-permanent`, выведена `--permanent`-конфигурация и выполнена проверка после `sudo firewall-cmd --reload`.

Использованные команды:

```bash
sudo firewall-cmd --zone=public --add-port=8080/tcp && sudo firewall-cmd --zone=public --list-all
sudo firewall-cmd --zone=public --remove-port=8080/tcp && sudo firewall-cmd --runtime-to-permanent && sudo firewall-cmd --zone=public --permanent --list-all
sudo firewall-cmd --reload && sudo firewall-cmd --zone=public --list-all
```
