# Samba

Работа выполнялась в виртуалке Arch Linux (`archlinux`, `192.168.100.249`).

## 1. Установка пакета Samba

Установлены сервер `samba` и консольный клиент `smbclient` (он пригодится для проверки доступа к группам), а также проверено наличие системных служб.

Использованные команды:

```bash
sudo pacman -S --needed samba smbclient
systemctl list-unit-files | grep -E '^(smb|nmb)' || true
```

Полученный результат:

```text

 there is nothing to do
nmb.service                                                               enabled         disabled
smb.service                                                               enabled         disabled
```

## 2. Что такое общий сетевой ресурс и зачем он нужен

**Общий сетевой ресурс** - это каталог (или принтер) на одном хосте, к которому открыт доступ по сети для других машин и юзеров (у Samba - по протоколу SMB/CIFS).

Зачем это нужно:
- хранить общие документы, проекты и учебные материалы централизованно в одном месте;
- спокойно обмениваться файлами между Linux, Windows и macOS без флешек и костылей;
- гибко разруливать права по юзерам и группам (кому чтение/запись, кому только чтение, а кому вообще закрыть вход);
- проще делать бэкапы - достаточно резервировать один файловый сервер, а не десятки машин.

## Подготовка групп, юзеров и каталогов

Созданы три группы (`smbgroup`, `teachers`, `students`) и три системных юзера с оболочкой `/usr/bin/nologin`, после чего они добавлены в базу Samba:
- `teacher1` - входит в `teachers` и `smbgroup` (полные права на чтение и запись);
- `student1` - входит в `students` (только чтение в ресурсе `[study]`);
- `outsider1` - не входит ни в одну из этих групп (отказ в доступе к закрытым группам).

Использованные команды:

```bash
sudo groupadd -f smbgroup && sudo groupadd -f teachers && sudo groupadd -f students
sudo useradd -M -s /usr/bin/nologin -G teachers,smbgroup teacher1
sudo useradd -M -s /usr/bin/nologin -G students student1
sudo useradd -M -s /usr/bin/nologin outsider1
id teacher1 && id student1 && id outsider1

for u in teacher1 student1 outsider1; do printf 'LabPass123\nLabPass123\n' | sudo smbpasswd -s -a "$u"; done && sudo pdbedit -L
```

Полученный результат:

### Каталоги, опубликованные по SMB

В `/srv/samba/` созданы четыре каталога с тестовыми файлами и соответствующими правами ФС:
- `/srv/samba/public_ro` - гостевой доступ без пароля, только чтение (`755`);
- `/srv/samba/private_rw` - доступ с аутентификацией, чтение и запись (`1777`);
- `/srv/samba/group_share` - полный доступ для группы `smbgroup` (`root:smbgroup`, `2770`);
- `/srv/samba/study` - ресурс для `teachers` (RW) и `students` (RO) (`root:teachers`, `2775`).

Проверка прав (`ls -ld /srv/samba/*`):

```text
drwxrws--- 1 root smbgroup 26 Nov 22 23:21 /srv/samba/group_share
drwxrwxrwt 1 root root     22 Nov 22 23:21 /srv/samba/private_rw
drwxr-xr-x 1 root root     30 Nov 22 23:21 /srv/samba/public_ro
drwxrwsr-x 1 root teachers 24 Nov 22 23:21 /srv/samba/study
```

## 3–6. Настройка ресурсов в `/etc/samba/smb.conf`

Перед редактированием сделана резервная копия `/etc/samba/smb.conf.bak`, затем файл открыт через `sudo nano /etc/samba/smb.conf` и в него добавлены секции для всех четырех ресурсов:

```ini
[global]
   workgroup = WORKGROUP
   server string = Samba Lab Server
   security = user
   map to guest = Bad User

[public_ro]
   path = /srv/samba/public_ro
   browseable = yes
   read only = yes
   guest ok = yes

[private_rw]
   path = /srv/samba/private_rw
   browseable = yes
   read only = no
   guest ok = no
   valid users = teacher1, student1, outsider1

[group_share]
   path = /srv/samba/group_share
   browseable = yes
   read only = no
   guest ok = no
   valid users = @smbgroup
   force group = smbgroup
   create mask = 0660
   directory mask = 2770

[study]
   path = /srv/samba/study
   browseable = yes
   guest ok = no
   valid users = @teachers, @students
   read only = yes
   write list = @teachers
   force group = teachers
   create mask = 0664
   directory mask = 2775
```

Как это работает:
- `[public_ro]` - пускает без пароля (`guest ok = yes` + `map to guest = Bad User`), но писать туда нельзя (`read only = yes`);
- `[private_rw]` - требует авторизацию (`guest ok = no`) и дает чтение/запись (`read only = no`);
- `[group_share]` - пускает только участников `@smbgroup` с полными правами;
- `[study]` - пускает только `@teachers` и `@students` (остальных отбивает сразу), по умолчанию только чтение (`read only = yes`), а запись разрешена только для `write list = @teachers`.

## 7. Проверка доступа от разных юзеров

Использованные команды:

```bash
echo "test upload" > /tmp/upload_test.txt
smbclient //127.0.0.1/public_ro -N -c 'ls; put /tmp/upload_test.txt guest_try.txt' || true
smbclient //127.0.0.1/study -U 'teacher1%LabPass123' -c 'ls; put /tmp/upload_test.txt teacher_ok.txt; ls' || true
smbclient //127.0.0.1/study -U 'student1%LabPass123' -c 'ls; put /tmp/upload_test.txt student_try.txt' || true
smbclient //127.0.0.1/study -U 'outsider1%LabPass123' -c 'ls' || true
```
