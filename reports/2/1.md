# Управление юзерами

I use arch btw

## 1. Создание юзеров 'user1' и 'user2'

Использованные команды:

```bash
sudo useradd -m -s /bin/bash user1
sudo useradd -m -s /bin/zsh user2
sudo passwd user1
sudo passwd user2
getent passwd user1 user2
```

Полученный результат:

```text
[sudo] пароль для darkextra: 
Новый пароль: 
Повторите новый пароль: 
passwd: password updated successfully
Новый пароль: 
Повторите новый пароль: 
passwd: password updated successfully
user1:x:1001:1001::/home/user1:/bin/bash
user2:x:1002:1002::/home/user2:/bin/zsh
```

Созданы пользователи `user1` (оболочка `/bin/bash`, домашний каталог `/home/user1`) и `user2` (оболочка `/bin/zsh`, домашний каталог `/home/user2`), обоим установлены пароли.

## 2. Создание группы `labusers` и добавление юзеров в группы

В Arch группой администраторов системы является `wheel` (`wheel:x:998:darkextra`).

Использованные команды:

```bash
sudo groupadd labusers
sudo usermod -aG wheel,labusers user1
sudo usermod -aG labusers user2
getent group labusers wheel && id user1 && id user2
```

Полученный результат:

```text
labusers:x:1003:user1,user2
wheel:x:998:darkextra,user1
uid=1001(user1) gid=1001(user1) группы=1001(user1),998(wheel),1003(labusers)
uid=1002(user2) gid=1002(user2) группы=1002(user2),1003(labusers)
```

Создана группа `labusers` (GID `1003`), юзер `user1` добавлен в группы `wheel` и `labusers`, юзер `user2` - в группу `labusers`.

## 3. Права доступа и просмотр прав в домашнем каталоге юзера

**Права доступа** в Linux определяют, какие действия разрешены с файлом или каталогом для трёх категорий субъектов: владельца (`u`), группы-владельца (`g`) и всех остальных юзеров (`o`).

Назначение базовых прав `r`, `w`, `x`:
- Для **файла**:
  - `r` (read, `4`) - чтение содержимого файла;
  - `w` (write, `2`) - изменение содержимого файла;
  - `x` (execute, `1`) - запуск файла как исполняемой программы или скрипта.
- Для **каталога**:
  - `r` (read, `4`) - просмотр списка имён файлов внутри каталога;
  - `w` (write, `2`) - создание, удаление и переименование файлов внутри каталога (при наличии `x`);
  - `x` (execute, `1`) - вход (переход) в каталог и доступ к метаданным/содержимому файлов внутри него по известному имени.

Использованная команда:

```bash
sudo ls -la /home/user1
```

Полученный результат:

```text
итого 24
drwx------ 2 user1 user1 4096 ноя 20 21:54 .
drwxr-xr-x 5 root  root  4096 ноя 20 21:54 ..
-rw-r--r-- 1 user1 user1   21 авг 14 23:25 .bash_logout
-rw-r--r-- 1 user1 user1   57 авг 14 23:25 .bash_profile
-rw-r--r-- 1 user1 user1  141 авг 14 23:25 .bashrc
-rw-r--r-- 1 user1 user1 4951 сен 12 10:15 .screenrc
```

Сам домашний каталог `/home/user1` (`.`) имеет права `drwx------` (`700`) - доступ только у владельца `user1`. Файлы конфигурации имеют права `-rw-r--r--` (`644`) - чтение и запись у `user1`, чтение у группы и остальных.

## 4. Создание файла и настройка прав доступа

Создание файла с правами на чтение всем и на запись только владельцу (`644`, `rw-r--r--`):

Использованные команды:

```bash
echo "Lab test file" > /tmp/lab_file.txt
chmod 644 /tmp/lab_file.txt
ls -l /tmp/lab_file.txt
```

Полученный результат:

```text
-rw-r--r-- 1 darkextra darkextra 14 ноя 20 21:57 /tmp/lab_file.txt
```

### 4.1 и 4.3. Временное выставление прав `777` и возврат минимально необходимых прав

Использованные команды:

```bash
chmod 777 /tmp/lab_file.txt && ls -l /tmp/lab_file.txt
chmod 644 /tmp/lab_file.txt && ls -l /tmp/lab_file.txt
```

Полученный результат:

```text
-rwxrwxrwx 1 darkextra darkextra 14 ноя 20 21:57 /tmp/lab_file.txt
-rw-r--r-- 1 darkextra darkextra 14 ноя 20 21:57 /tmp/lab_file.txt
```

### 4.2. Почему права `777` обычно избыточны

Права `777` (`rwxrwxrwx`) нарушают принцип минимальных привилегий:
- любой локальный юзер или процесс в системе получает возможность изменять или перезаписывать содержимое файла (риск подмены данных или внедрения вредоносного содержимого);
- выставляется бит выполнения `x` для обычного текстового файла, которому он не нужен.

## 5. Встроенная учётная запись администратора в Linux

Встроенная учётная запись суперюзера (администратора) в Linux называется **`root`** (имеет идентификатор `UID 0`).

## 6. Выполнение одной команды с административными правами

Для выполнения одной команды с правами суперюзера используется утилита **`sudo`**:

```bash
sudo <команда>
```

(Альтернативный вариант при наличии пароля `root`: `su -c '<команда>'`.)

## 7. Ограничения возможностей суперюзера

У `root` нет абсолютной возможности выполнить любую операцию. Примеры ограничений, не связанных с обычными дискреционными файловыми правами (`rwx`):
- **Файловая система, смонтированная в режиме «только для чтения» (`ro`)** - даже `root` не может записывать в неё файлы без перемонтирования (а в случае аппаратной защиты от записи или носителя вроде CD-ROM запись невозможна вовсе).
- **Неизменяемый атрибут файла (`immutable`, устанавливается через `chattr +i`)** - даже `root` не сможет изменить или удалить файл, пока атрибут не будет снят.
- **Мандатный контроль доступа (SELinux / AppArmor), Linux Capabilities, контейнеры и `kernel_lockdown`** - политики безопасности ядра и ограничения возможностей процессов могут запрещать операции даже процессу с `UID 0`.

## 8. Удаление юзера `user2` с сохранением домашнего каталога

Использованные команды:

```bash
sudo userdel user2
id user2
ls -ld /home/user2
```

Полученный результат:

```text
id: «user2»: такого юзера нет
drwxr-xr-x 2 1002 1002 4096 ноя 20 21:54 /home/user2
```

Команда `userdel` без флага `-r` удалила учётную запись `user2` (подтверждено выводом `id`), но сохранила его домашний каталог `/home/user2` (владелец и группа отображаются числовыми идентификаторами `1002 1002`).

## 9. Изменение владельца и группы файла или каталога

Для изменения владельца и группы используется команда `chown` (формат `chown <владелец>:<группа> <путь>`, для каталога рекурсивно - с флагом `-R`; только группу также можно менять через `chgrp`).

Использованные команды:

```bash
sudo chown user1:labusers /tmp/lab_file.txt
ls -l /tmp/lab_file.txt
```

Полученный результат:

```text
-rw-r--r-- 1 user1 labusers 14 ноя 20 21:57 /tmp/lab_file.txt
```

Владелец файла `/tmp/lab_file.txt` изменён на `user1`, группа-владелец - на `labusers`.

## 10. UID, основной GID и дополнительные группы `user1`

Использованная команда:

```bash
id user1
```

Полученный результат:

```text
uid=1001(user1) gid=1001(user1) группы=1001(user1),998(wheel),1003(labusers)
```

- **UID:** `1001` (`user1`)
- **Основной GID:** `1001` (`user1`)
- **Дополнительные группы:** `998` (`wheel`), `1003` (`labusers`)
