# Запрещаем

## 1 и 2. Запрет входа юзеру `user1` и проверка состояния учётной записи

Для запрета входа (как по паролю, так и на уровне срока действия учётной записи через PAM/SSH) использована команда `usermod -L -e 1`, которая одновременно блокирует пароль (`-L`) и устанавливает дату истечения учётной записи в прошлое (`-e 1` - 2 января 1970 года).

Использованные команды:

```bash
sudo usermod -L -e 1 user1
sudo passwd -S user1
sudo chage -l user1
```

Полученный результат:

```text
user1 L 2026-11-20 0 99999 7 -1
Последнее изменение пароля					: ноя 20, 2026
Срок действия пароля истекает					: никогда
Пароль становится неактивным					: никогда
Срок действия учётной записи истекает				: янв 02, 1970
Минимальное количество дней между сменами пароля		: 0
Максимальное количество дней между сменами пароля		: 99999
Количество дней предупреждения до истечения срока действия пароля	: 7
```

Состояние учётной записи подтверждается:
- выводом `passwd -S user1` - флаг `L` (Locked) означает, что пароль заблокирован;
- выводом `chage -l user1` - срок действия учётной записи истёк (`янв 02, 1970`).

## 3. Другие способы запретить интерактивный вход

1. **Назначение запрещающей оболочки (shell)** - смена оболочки юзера на `/usr/bin/nologin` (или `/sbin/nologin`, `/bin/false`):
   ```bash
   sudo usermod -s /usr/bin/nologin user1
   ```
   При попытке интерактивного входа система сразу завершает сеанс.
2. **Блокировка пароля отдельной командой `passwd -l <user>`** - добавляет символ `!` перед хешем пароля в `/etc/shadow`, запрещая аутентификацию по паролю (но не по SSH-ключам).
3. **Ограничение доступа через PAM** - настройка модуля `pam_access` (`/etc/security/access.conf`) или временное создание файла `/etc/nologin` (запрещает вход всем обычным юзерам, кроме `root`).
4. **Ограничение удалённого доступа в SSH** - добавление юзера в директиву `DenyUsers` (или исключение из `AllowUsers`) в `/etc/ssh/sshd_config`.

## 4. Можно ли создать двух пользователей с одинаковым `username`?

Стандартными средствами администрирования (`useradd`) создать двух пользователей с одинаковым именем **нельзя** - утилита вернёт ошибку, так как `username` должно быть уникальным.

Если же вручную продублировать имя в `/etc/passwd`, система окажется в некорректном состоянии: при поиске учётной записи по имени (NSS/PAM) всегда будет возвращаться только первая встретившаяся запись, а вторая станет фактически недоступной для обычного входа и вызовет сбои утилит управления юзерами.

## 5. Можно ли создать двух пользователей с одинаковым UID? Что увидит система?

**Да**, технически это возможно (например, с помощью ключа `-o` утилиты `useradd`: `useradd -o -u <UID>` или путём ручного редактирования `/etc/passwd`).

**Последствия и поведение системы:**
- Ядро Linux проверяет права доступа исключительно по числовому `UID`, а не по имени юзера. Поэтому обе учётные записи будут обладать **одинаковыми правами** и полным доступом к файлам и процессам друг друга (с точки зрения ядра это один и тот же юзер).
- При обратном преобразовании `UID -> username` (в выводе `ls -l`, `ps`, журналах аудита и т.д.) системные утилиты, как правило, будут показывать **первое имя юзера** с данным UID в `/etc/passwd`, что затрудняет аудит и администрирование.

## 6. Восстановление возможности входа для `user1`

Использованные команды:

```bash
sudo usermod -U -e "" user1
sudo passwd -S user1
sudo chage -l user1
su - user1 -c 'whoami'
```

Полученный результат:

```text
user1 P 2026-11-20 0 99999 7 -1
Последнее изменение пароля					: ноя 20, 2026
Срок действия пароля истекает					: никогда
Пароль становится неактивным					: никогда
Срок действия учётной записи истекает				: никогда
Минимальное количество дней между сменами пароля		: 0
Максимальное количество дней между сменами пароля		: 99999
Количество дней предупреждения до истечения срока действия пароля	: 7
Пароль: 
user1
```

Команда `usermod -U -e "" user1` разблокировала пароль и сняла ограничение по сроку действия учётной записи. Статус в `passwd -S` сменился на `P` (пароль активен), срок действия в `chage -l` стал `никогда`, а успешная аутентификация через `su - user1 -c 'whoami'` подтвердила, что вход снова разрешён.
