# Установка и управление пакетами и службами

## 1. Установка пакетов

```bash
sudo pacman -S samba bind bind-tools
yay -S python-requests
```

## 2. Информация об установленных пакетах

### 2.1


## 3. Службы

Связанные службы в Arch Linux:
- Для Samba: `smb.service`
- Для BIND: `named.service`

Чтобы включить (запустить) службу:
```bash
systemctl start smb nmb named
```

Автозагрузка:
```bash
systemctl enable --now smb nmb named
```

### 5.3
Команда `systemctl show smb -p User` возвращает пустое значение, что означает запуск от пользователя `root`. Проверка процессов с помощью команды `ps -o user,pid,cmd -C smbd` подтверждает, что главный процесс и его воркеры работают от имени `root`. Службе Samba необходимы права суперпользователя для аутентификации клиентов и динамического переключения прав доступа при работе с файлами разных пользователей (`show -p User` работает только для пары служб, где юзер явно задан, по типу `polkit` и т.д.).

## 6. Вывод

Краткий вывод о различии между установкой, запуском и автозапуском:

- **Установка пакета (`pacman -S`):** Это просто скачивание архива с программой из репозитория и распаковка его файлов (бинарников, библиотек, конфигов) на жесткий диск. Программа еще не работает.
- **Запуск службы (`systemctl start`):** Это запуск исполняемого файла программы (создание процесса в оперативной памяти) прямо сейчас, в текущем сеансе работы ОС. Если компьютер перезагрузить, служба сама не запустится.
- **Включение автозапуска (`systemctl enable`):** Это создание символических ссылок в специальных директориях systemd (например, `/etc/systemd/system/multi-user.target.wants/`). Благодаря этому система знает, что при следующей загрузке компьютера эту службу нужно запустить автоматически. При этом команда `enable` без ключа `--now` не запускает службу в данный момент времени, а лишь планирует её запуск на следующую загрузку.
