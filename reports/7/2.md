# Конфигурируем для удобства

## 1. Где хранятся настройки SSH-клиента

- **Пользовательские настройки:** `~/.ssh/config` (у юзера `xen` - `/home/xen/.ssh/config`, имеют приоритет над системными).
- **Системные настройки (общие для всех юзеров):** `/etc/ssh/ssh_config` (и файлы в `/etc/ssh/ssh_config.d/*.conf`).

## 2–4 и 7. Создание `~/.ssh/config` с псевдонимом `lab-vm`

Создан файл `/home/xen/.ssh/config` с правами `600` (SSH-клиент требует, чтобы конфиг не был доступен на запись другим юзерам) и блоком `Host lab-vm` с параметрами `HostName`, `User` и `Port`.

Использованные команды:

```bash
mkdir -p ~/.ssh && chmod 700 ~/.ssh
cat > ~/.ssh/config <<'EOF'
Host lab-vm
    HostName 192.168.100.249
    User xen
    Port 22
EOF
chmod 600 ~/.ssh/config
ls -l ~/.ssh/config && cat ~/.ssh/config
```

Полученный результат:

```text
-rw------- 1 xen xen 66 Nov 22 22:50 /home/xen/.ssh/config
Host lab-vm
    HostName 192.168.100.249
    User xen
    Port 22
```

В конфигурации нет ни паролей, ни приватных ключей.

## 5. Проверка подключения по короткому псевдониму

Использованная команда:

```bash
ssh lab-vm 'whoami && uname -n'
```

Полученный результат:

```text
xen@192.168.100.249's password: 
xen
archlinux
```

Подключение по короткому псевдониму `ssh lab-vm` прошло успешно без явного указания имени юзера, IP-адреса и порта.

## 6. Про `ProxyJump` (jump host)

В текущей схеме подключение к `192.168.100.249` идет напрямую, без промежуточного jump-сервера. Если подключение выполняется через jump host, в `~/.ssh/config` добавляется отдельный блок для jump-сервера и директива `ProxyJump` у целевого хоста (пример структуры):

```sshconfig
Host jump-server
    HostName <ip-jump-сервера>
    User <юзер>
    Port 22

Host target-server
    HostName <внутренний-ip>
    User <юзер>
    Port 22
    ProxyJump jump-server
```
