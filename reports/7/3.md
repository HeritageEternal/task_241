# Ключи

## 1–2. Что такое SSH-ключи, зачем они нужны и как создать пару ключей

**SSH-ключи** - это асимметричная криптографическая пара из **приватного** (секретного) и **публичного** (открытого) ключей. Публичный ключ размещается на сервере, а приватный хранится только у клиента.

Зачем они нужны:
- гораздо устойчивее к перебору (брутфорсу), чем пароли;
- позволяют входить на сервер без постоянного ввода пароля учетной записи (удобно для работы и автоматизации);
- дают возможность полностью отключить парольную аутентификацию на сервере.

**Почему приватный ключ нельзя передавать другим юзерам:** приватный ключ подтверждает твою личность при аутентификации. Любой, кто получит приватный ключ (особенно без passphrase), сможет без пароля зайти от твоего имени на все серверы, где добавлен соответствующий публичный ключ.

Пара ключей генерируется утилитой **`ssh-keygen`**.

## 3. Генерация пары ключей `ed25519`

Использованные команды:

```bash
ssh-keygen -t ed25519 -C "xen@archlinux-lab" -f ~/.ssh/id_ed25519 -N ""
ls -l ~/.ssh/id_ed25519 ~/.ssh/id_ed25519.pub
```

## 4–6. Копирование ключа на сервер, проверка входа без пароля и права

На сервере публичные ключи для входа хранятся в файле **`~/.ssh/authorized_keys`** (`/home/xen/.ssh/authorized_keys`).

Использованные команды:

```bash
ssh-copy-id -i ~/.ssh/id_ed25519.pub lab-vm
ssh -o BatchMode=yes lab-vm 'echo "Login by key OK: $(whoami)" && ls -ld ~/.ssh && ls -l ~/.ssh/authorized_keys'
```

Полученный результат:

```text
/usr/bin/ssh-copy-id: INFO: Source of key(s) to be installed: "/home/xen/.ssh/id_ed25519.pub"
/usr/bin/ssh-copy-id: INFO: attempting to log in with the new key(s), to filter out any that are already installed
/usr/bin/ssh-copy-id: INFO: 1 key(s) remain to be installed -- if you are prompted now it is to install the new keys
xen@192.168.100.249's password: 

Number of key(s) added: 1

Now try logging into the machine, with: "ssh -i /home/xen/.ssh/id_ed25519 'lab-vm'"
and check to make sure that no unwanted key(s) were added.

Login by key OK: xen
drwx------ 1 xen xen 152 Nov 22 22:51 /home/xen/.ssh
-rw------- 1 xen xen  99 Nov 22 22:51 /home/xen/.ssh/authorized_keys
```

- Пароль учетной записи при подключении больше **не запрашивается** (подтверждено опцией `-o BatchMode=yes`).
- Права корректные: на каталог `/home/xen/.ssh` - `drwx------` (`700`), на файл `/home/xen/.ssh/authorized_keys` - `-rw-------` (`600`).

## 7–9. Запрет парольной аутентификации и проверка

В `/etc/ssh/sshd_config.d/99-lab.conf` оставлен вход по ключам (`PubkeyAuthentication yes`) и отключена парольная аутентификация (`PasswordAuthentication no` и `KbdInteractiveAuthentication no`). Перед перезапуском службы конфигурация проверена командой `sudo sshd -t`.

Использованные команды:

```bash
sudo tee /etc/ssh/sshd_config.d/99-lab.conf > /dev/null <<'EOF'
PermitRootLogin no
MaxAuthTries 3
DenyUsers ssh-user
PubkeyAuthentication yes
PasswordAuthentication no
KbdInteractiveAuthentication no
EOF
sudo sshd -t && echo "sshd config OK"
sudo systemctl restart sshd.service
```

Полученный результат:

```text
sshd config OK
```

### Проверка входа по ключу и отказа при попытке парольной аутентификации

Не закрывая текущую рабочую сессию, проверили оба варианта подключения:

```bash
ssh -o BatchMode=yes lab-vm 'echo "Key auth works: $(whoami)"'
ssh -o PubkeyAuthentication=no -o PreferredAuthentications=password,keyboard-interactive lab-vm 'whoami' || true
```

Полученный результат:

```text
Key auth works: xen
xen@192.168.100.249: Permission denied (publickey).
```

Вход по ключу работает без проблем (`Key auth works: xen`), а попытка входа по паролю сразу отбивается с ошибкой `Permission denied (publickey).` - парольная аутентификация полностью запрещена.
