# Продолжаем

Работа выполнялась в виртуальной машине с Arch Linux, куда были добавлены новые виртуальные VirtIO-диски через QEMU.

## 1. Содержимое `/etc/fstab` до изменений

`/etc/fstab` - это конфиг, в котором прописано, какие файловые системы и разделы система должна монтировать автоматически при загрузке (или по команде `mount -a`), куда их монтировать, с какими опциями и нужно ли проверять их `fsck`.

Использованная команда:

```bash
cat /etc/fstab
```

## 6–7. Ручное монтирование и создание тестовых файлов

Использованные команды:

```bash
sudo mkdir -p /mnt/labdisk && sudo mount /dev/vdb1 /mnt/labdisk
findmnt /mnt/labdisk
sudo touch /mnt/labdisk/file1.txt /mnt/labdisk/file2.txt && echo "hello ext4" | sudo tee /mnt/labdisk/file1.txt > /dev/null && ls -la /mnt/labdisk
```

Полученный результат:

```text
TARGET       SOURCE    FSTYPE OPTIONS
/mnt/labdisk /dev/vdb1 ext4   rw,relatime
total 24
drwxr-xr-x 3 root root  4096 Nov 21 01:37 .
drwxr-xr-x 1 root root    14 Nov 21 01:37 ..
-rw-r--r-- 1 root root    11 Nov 21 01:37 file1.txt
-rw-r--r-- 1 root root     0 Nov 21 01:37 file2.txt
drwx------ 2 root root 16384 Nov 21 01:36 lost+found
```

Раздел `/dev/vdb1` смонтирован в `/mnt/labdisk`, на нём созданы тестовые файлы `file1.txt` и `file2.txt`.

## 8. Отмонтирование и проверка каталога + получение UUID

Использованные команды:

```bash
sudo umount /mnt/labdisk
ls -la /mnt/labdisk
sudo blkid /dev/vdb1
```

Полученный результат:

```text
total 0
drwxr-xr-x 1 root root  0 Nov 21 01:37 .
drwxr-xr-x 1 root root 14 Nov 21 01:37 ..
/dev/vdb1: UUID="4e70299d-c36f-42c4-8aa1-90fafdb0b609" BLOCK_SIZE="4096" TYPE="ext4" PARTUUID="0fe321f3-db52-466f-ab93-716713eebc27"
```

После `umount` каталог `/mnt/labdisk` оказался пустым. Это нормально: файлы физически лежат в файловой системе на разделе `/dev/vdb1`, а `/mnt/labdisk` - это просто пустой каталог-точка входа на корневой ФС. Когда раздел отмонтирован, содержимое диска через него не видно.

UUID созданной ФС: `4e70299d-c36f-42c4-8aa1-90fafdb0b609`.

## 9–11. Настройка `/etc/fstab` по UUID и проверка до перезагрузки

Использовать UUID вместо `/dev/vdb1` надёжнее: имена устройств могут поменяться, если добавить или переставить диски, а UUID жёстко привязан к конкретной ФС.

Использованные команды:

```bash
sudo cp /etc/fstab /etc/fstab.bak
echo 'UUID=4e70299d-c36f-42c4-8aa1-90fafdb0b609 /mnt/labdisk ext4 defaults 0 2' | sudo tee -a /etc/fstab
sudo findmnt --verify && sudo mount -a && findmnt /mnt/labdisk
```

Полученный результат:

```text
UUID=4e70299d-c36f-42c4-8aa1-90fafdb0b609 /mnt/labdisk ext4 defaults 0 2
   [W] your fstab has been modified, but systemd still uses the old version;
       use 'systemctl daemon-reload' to reload

0 parse errors, 0 errors, 1 warning
mount: (hint) your fstab has been modified, but systemd still uses
       the old version; use 'systemctl daemon-reload' to reload.
TARGET       SOURCE    FSTYPE OPTIONS
/mnt/labdisk /dev/vdb1 ext4   rw,relatime
```

`findmnt --verify` показал `0 parse errors, 0 errors`, а `mount -a` успешно примонтировал `/dev/vdb1` в `/mnt/labdisk`.

## 12. Перезагрузка и проверка автоматического монтирования

После `sudo reboot` были выполнены проверочные команды:

```bash
findmnt /mnt/labdisk
ls -la /mnt/labdisk
```

Полученный результат:

```text
TARGET       SOURCE    FSTYPE OPTIONS
/mnt/labdisk /dev/vdb1 ext4   rw,relatime
total 24
drwxr-xr-x 3 root root  4096 Nov 21 01:37 .
drwxr-xr-x 1 root root    14 Nov 21 01:37 ..
-rw-r--r-- 1 root root    11 Nov 21 01:37 file1.txt
-rw-r--r-- 1 root root     0 Nov 21 01:37 file2.txt
drwx------ 2 root root 16384 Nov 21 01:36 lost+found
```

После перезагрузки раздел `/dev/vdb1` смонтировался автоматически, и ранее созданные файлы `file1.txt` и `file2.txt` снова доступны.

## Критерий приёмки

Все пункты подтверждены реальным выводом с ВМ:
- показан `/etc/fstab` до изменений;
- выведен `lsblk` после добавления дисков;
- создана GPT-таблица и раздел `/dev/vdb1` (вывод `sfdisk` и `fdisk -l`);
- показана команда и результат создания `ext4`;
- подтверждено ручное монтирование и создание `file1.txt`, `file2.txt`;
- подтверждено, что после `umount` каталог `/mnt/labdisk` пуст;
- получен UUID (`4e70299d-c36f-42c4-8aa1-90fafdb0b609`) и добавлена строка в `/etc/fstab`;
- проведена проверка `findmnt --verify` и `mount -a` до перезагрузки;
- после `reboot` подтверждено автоматическое монтирование и сохранность файлов.
