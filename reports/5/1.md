# Юниты

## 1. Что такое systemd unit

**systemd unit** - это базовый объект, которым управляет система инициализации `systemd`, описанный в специальном конфиг-файле (unit-файле). Юнитами бывают не только фоновые службы (`.service`), но и таймеры (`.timer`), точки монтирования (`.mount`), сокеты (`.socket`), таргеты (`.target`) и другие ресурсы системы.

## 5–6. Отключение и возврат в автозагрузку

Использованные команды:

```bash
sudo systemctl disable systemd-timesyncd.service && systemctl is-enabled systemd-timesyncd.service || true
sudo systemctl enable systemd-timesyncd.service && systemctl is-enabled systemd-timesyncd.service
```

Полученный результат:

```text
Removed '/etc/systemd/system/dbus-org.freedesktop.timesync1.service'.
Removed '/etc/systemd/system/sysinit.target.wants/systemd-timesyncd.service'.
disabled
Created symlink '/etc/systemd/system/dbus-org.freedesktop.timesync1.service' → '/usr/lib/systemd/system/systemd-timesyncd.service'.
Created symlink '/etc/systemd/system/sysinit.target.wants/systemd-timesyncd.service' → '/usr/lib/systemd/system/systemd-timesyncd.service'.
enabled
```

`disable` удалил симлинки автозапуска и перевёл сервис в `disabled`, а `enable` восстановил оба симлинка обратно (`enabled`).

## 7. Разница между `active`, `enabled`, `disabled`, `failed` и между текущим состоянием и автозапуском

Важно разделять **текущее состояние** (работает ли сервис прямо сейчас) и **настройку автозапуска** (будет ли он стартовать сам при загрузке системы):

- **`active`** - текущее состояние: юнит запущен прямо сейчас (пример: `systemd-timesyncd.service` после запуска - `active (running)`).
- **`failed`** - текущее состояние: юнит упал с ошибкой при запуске или в процессе работы (пример из следующего задания: `lab-sysinfo.service` с неверным `ExecStart` - `Active: failed (Result: exit-code)`).
- **`enabled`** - автозапуск: созданы симлинки в `.wants/`, юнит будет стартовать автоматически при загрузке (пример: `systemd-timesyncd.service` - `enabled`).
- **`disabled`** - автозапуск: симлинков нет, сам при загрузке не стартует, но руками его запустить можно (пример: `sshd.service` - `disabled`).

Сервис спокойно может быть одновременно `active` + `disabled` (запустили руками один раз) или `inactive` + `enabled` (в автозагрузке стоит, но сейчас остановлен вручную).

## 8–9. Что такое systemd timers и пример таймера в системе

**systemd timers** - это юниты вида `*.timer`, встроенная в `systemd` замена `cron`. Они умеют запускать связанные `.service`-юниты по календарному расписанию (`OnCalendar`) или с задержкой после загрузки/предыдущего запуска, при этом всё логируется прямо в `journald`.

```bash
systemctl list-timers --all --no-pager
```

### Пример конкретного таймера: `shadow.timer`

Использованная команда:

```bash
systemctl cat shadow.timer --no-pager
```

Полученный результат:

```text
# /usr/lib/systemd/system/shadow.timer
[Unit]
Description=Daily verification of password and group files

[Timer]
OnCalendar=daily
AccuracySec=12h
Persistent=true
```

Таймер **`shadow.timer`** по умолчанию запускает одноимённый юнит **`shadow.service`** (это видно и в столбце `ACTIVATES` вывода `list-timers`), который ежедневно проверяет целостность файлов паролей и групп.
