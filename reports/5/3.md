## 1, 4 и 7. Журнал службы SSH за текущую загрузку и событие собственного подключения

Поскольку изначально `sshd.service` был остановлен (`disabled`, `inactive`), для теста он был запущен вручную, выполнено локальное подключение по SSH под юзером `darkextra`, после чего снят журнал за текущую загрузку (`-b`) и `sshd.service` остановлен обратно.

Использованные команды:

```bash
sudo systemctl start sshd.service
ssh -o ConnectTimeout=5 -o StrictHostKeyChecking=accept-new darkextra@127.0.0.1 'echo "SSH OK: $(whoami)"'
sudo journalctl -u sshd.service -b --no-pager
```

Полученный результат:

## 6. Где `journald` хранит данные и чем это отличается от обычного текстового лога

Проверка расположения каталогов на системе:

```bash
ls -la /var/log/journal /run/log/journal 2>&1 || true
```

Полученный результат:

```text
/run/log/journal:
итого 0
drwxr-sr-x+ 2 root systemd-journal 40 ноя 21 10:17 .
drwxr-xr-x  3 root root            60 ноя 21 09:28 ..

/var/log/journal:
итого 0
drwxr-sr-x+ 1 root systemd-journal           76 фев 14  2026 .
drwxr-xr-x  1 root root                     452 ноя 21 10:17 ..
drwxr-sr-x+ 1 root systemd-journal        15592 ноя 21 12:24 c938ff5c69f54907b742a4a1ede4f063
drwxr-sr-x  1 root systemd-journal-remote     0 фев 14  2026 remote
```

- **Где хранятся данные:** постоянные журналы лежат в `/var/log/journal/<machine-id>/` (в моей системе - `/var/log/journal/c938ff5c69f54907b742a4a1ede4f063/`), а временные в памяти - в `/run/log/journal/`.
- **Почему это не обычный текстовый лог:** `journald` пишет события в индексированный структурированный **бинарный формат** (`*.journal`). В отличие от обычного `.log`-файла, каждая запись хранит набор структурированных метаданных (имя юнита, PID, UID, приоритет, boot ID, микросекундную метку времени), за счёт чего работает мгновенная фильтрация, сжатие, лимитирование объёма и защита целостности.
- **Доступ без `journalctl`:** просто открыть `cat`/`less` не выйдет (бинарник), но читать журнал можно программно через API `libsystemd` (`sd-journal`, например из C или `python-systemd`), либо настроить форвардинг в `rsyslog`/`syslog-ng`, чтобы дублировать события в обычные текстовые файлы.
